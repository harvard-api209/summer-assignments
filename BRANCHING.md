# Branching model

One branch is the source of truth; the student branch is generated from it.

| Branch | Role | Who edits it |
|--------|------|--------------|
| `2026-refresh` | Canonical: website (`docs/`), notebooks (`assignments/`), data, scripts, plans | Teaching team (everything is edited here) |
| `posit-cloud-2026` | Student-facing bundle pulled by the Posit Cloud project (assignments, data, scripts, student README) | **Nobody.** Regenerated by `.github/workflows/student-branch.yml` on every push to the canonical branch that touches student files |
| `main` | Stable; receives the refresh branch at season end | Merge target only |
| `archive/2025` | Frozen 2025 season | Nobody (consider converting to a tag) |

## How notebook edits flow

0. After editing `assignments/*.Rmd`, also run
   `python3 tools/generate_web_assignments.py` so the in-browser versions
   under `docs/web-assignments/` stay in sync, and run
   `bash tools/verify.sh` before pushing (see `docs/DEVELOPMENT.md`).
1. Edit `assignments/*.Rmd` (or `data/`, `scripts/`) on `2026-refresh` and push.
2. The GitHub Action rebuilds `posit-cloud-2026` automatically: it replaces
   the student branch's tree with the student folders plus
   `student-bundle/README.md` (as `README.md`) and `student-bundle/gitignore`
   (as `.gitignore`), committed on top of the branch history (no force push).
3. In the Posit Cloud master project, `git pull` — it fast-forwards as before.

To change the **student-facing README or .gitignore**, edit the copies in
`student-bundle/` on the canonical branch; never edit them on
`posit-cloud-2026` directly (the next sync would overwrite them).

## Season-end checklist (when 2026 work is done)

1. Merge `2026-refresh` into `main`.
2. In the same merge, edit `.github/workflows/student-branch.yml`:
   `branches: [2026-refresh]` → `branches: [main]`.
3. Switch the GitHub Pages source from `2026-refresh:/docs` to `main:/docs`
   (Settings → Pages). **This is the step most likely to be forgotten** — the
   site silently keeps serving the stale branch otherwise.
4. Tag the season (`git tag v2026-final && git push --tags`) and delete or
   archive `2026-refresh`.
5. Next season: branch `2027-refresh` off `main`; keep the same generated
   student branch (rename it to `posit-cloud` at that point if desired — the
   Posit project then needs a one-time `git fetch && git checkout posit-cloud`).
